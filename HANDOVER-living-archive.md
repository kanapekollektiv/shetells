## 3. Architecture

Three files, no build step. `living-archive.html` holds the markup, the CSS and
the script inline. `lang.js` holds the interface strings. `content.js` holds
every word on the map. No bundler, no framework, nothing to compile.

| Concept | Where | Notes |
|---|---|---|
| Canvas | `.canvas-inner` | Currently 4200×2300. **Recomputed by the packer, don't hand-edit** |
| Pan/zoom | `#viewport`, `translate(tx,ty) scale(s)` | |
| Categories | `CATS` | 9 clusters, each `{key, label, color}`; `label` is bilingual |
| Cluster centres | `CENTERS` | Drives connection lines only. **Regenerated by the packer** |
| Connection lines | `CONNECTIONS` | Open beziers; `bend` sets curve |
| Card layout | `CARDS_LAYOUT` | `[cats[], x, y, w, h, contentId, layout]`. Geometry only |
| Card content | `CONTENT`, in `content.js` | Every string, keyed by the id above |
| Resolved cards | `CARDS` | Built at load from the two above, in the old shape |
| Side panels | `SECTIONS` | Only `hypersea` has an entry. Largely superseded — see §7 |

### The content split

Copy used to live inline in the card array, which made single lines 8,000
characters long and put the whole map one stray apostrophe away from a blank
page. It now lives in `content.js`, keyed by the id in the sixth slot of each
card. `CARDS_LAYOUT` holds geometry, `content.js` holds words and media paths,
and a resolver right below the array rebuilds the old
`[cats, x, y, w, h, title, content]` shape, so nothing downstream changed.

For whoever edits the copy:

* Strings are written in backticks, so apostrophes are safe.
* A real line break is a paragraph break. Indentation is stripped at load by
  `dedent()`, so keep the text lined up with its entry.
* `txt` is the card, `full` is the popup. The code already falls back to `txt`,
  so only write `full` when the popup genuinely says more.
* `note: 'ml'` expands to the standard ML sentence, held once in `ML_NOTE`.
* An id with no entry, or an entry no card uses, is reported in the browser
  console at load. Neither is visible on the map otherwise.

The migration was verified by resolving all 66 cards and deep-comparing them
against the pre-migration array: identical. Re-verified after the ids were
renamed to readable slugs.

### Card content types

The 7th element decides what renders. All of these are live and in use:

- `{ img, alt }` + optional `caption`, `link`, `credit`, `full`, `sources`, `note`, `mWidth`
- `{ vid }` + optional `poster` — lazily played by `updateVideos()`, **paused below 0.45 zoom**, which is why `poster` matters
- `{ gallery: [{src, alt, caption}] }` — carousel. Frames ending `.mp4` render as
  video. Optional `full`, `entries`, `sources`, `note`
- `{ link, label }` — external link pill
- `{ goTo: 'clusterkey', label }` — internal pill, flies to another cluster
- `{ txt, full }` — text card; `txt` on the card, `full` in the popup
- `{ credits }` + optional `mtNotice: true`
- `null` with a `title` — plain placeholder card
- `null` with no title — coloured band placeholder

Cross-cluster tagging: `[['hypersea','sargassum'], …]`. The **first** tag is the
owning cluster. Extra tags render as dots under the card.

These shapes are unchanged by the content split; they are simply written in
`content.js` now rather than inline.

### Mechanisms you must understand before editing

**`L(value)`** — the bilingual helper. Any string in `CATS`, `CARDS` or
`SECTIONS` may be a plain string or `{ en, pt }`. `L()` returns the active
language and falls back to English. **Every consumer must call it.** Forgetting
it prints `[object Object]` into the DOM — that has happened twice.

**`onLang(fn)`** — registers a callback that re-applies text on language change.
The map is never rebuilt, so pan, zoom and float phase survive a switch.

**`stackBelow: true, gap: n`** — positions a card from the bottom of the
**previous card in the `CARDS` array**, recomputed on every language change.
Essential because text cards hug their content and Portuguese runs 10–20%
longer. Several collisions were caused by fixed `y` under a text card.

**The packer**, `tools/pack_clusters.py`. Cluster positions, `CENTERS`, canvas
size and the SVG size are all generated by it, so re-run it after every content
change. Card positions *within* a cluster are hand-authored; the packer
translates each cluster as a rigid group.

```bash
python3 tools/pack_clusters.py            # dry run, prints what would move
python3 tools/pack_clusters.py --write    # apply
```

Rows, margins, the 210px horizontal gap, the 320px row gap and the per-cluster
vertical stagger are constants at the top of the file, each one commented. Every
row needs at least one cluster at stagger 0, or it exits rather than guess. It
takes an optional file path, which is how to try a layout change on a copy
before touching the real page.

It is idempotent, and that is the check: run it twice, the second run should say
`nothing to do`. Run against the layout as it stood on 2026-08-18 it reproduced
all nine cluster positions and the 4200×2300 canvas exactly, changing only the
whitespace and ordering of the `CENTERS` block, which it now writes in row
order.

### Traps that have already bitten

- **No lazy loading on map card images.** The canvas is transformed, and moving a
  transformed ancestor does not re-run the browser's intersection check, so
  images in far clusters never loaded. Panels and mobile notes scroll normally
  and keep `loading="lazy"`.
- **Authored `h` vs rendered height.** Text cards ignore authored height. The
  packer uses authored values, so author them generously or the bbox is wrong.
- **Click detection** is a per-card `pointerdown`/`pointerup` pair, distance
  < 12px and time < 600ms, deliberately bypassing the pan handler. If clicks
  break after a refactor, this is why.
- **Always validate after a large edit.** Two syntax errors (doubled `}`) took
  the whole script out. Extract and check:
  ```bash
  python3 -c "import io,re;s=io.open('living-archive.html',encoding='utf-8').read();io.open('/tmp/page.js','w',encoding='utf-8').write(re.search(r'  <script>\n(.*?)\n  </script>',s,re.S).group(1))" && node --check /tmp/page.js
  ```

## 4. Hard constraints

1. **Never rotate cards.** The float animation drifts x/y only. A live `rotate()`
   was found and removed; do not reintroduce it.
2. **Never edit the user's written copy.** Verbatim, including the typo "Here you
   can fin some related reading" in the Hypersea intro. Exception: they gave
   explicit permission for the Sargassum text, where spelling was corrected.
3. **No dashes in prose.** No em dashes, no hyphenated compounds where avoidable.
   Applies to both languages.
4. **Portuguese is European (pt-PT), addressing the reader as *tu*.** The whole
   of `lang.js` was converted. `document.documentElement.lang` is `pt-PT`.
5. **Text I write carries the ML note**, via `note:`. Copy supplied by the user
   does not. The participant's handwritten water memory does not.
6. Lightbox is `object-fit: contain` — fit, never crop.

## 6. Features built this session

- **Bilingual throughout** via `lang.js` (93 EN / 94 PT keys, parity verified).
  `archive.*` keys: `back`, `contribute`, `hint`, `placeholder`, `read`,
  `readmore`, `sources`.
- **Mobile layout** under 768px: the map is replaced by a plain list of clusters,
  tapping one opens that cluster's content as a scrolling "field notes" column.
  Built from the same `CATS`/`CARDS` data, so clusters gain a mobile view as soon
  as they have cards. A card's `title` leads its section, since on a phone there
  is no card to carry it, and a gallery renders everything the desktop popup
  shows: carousel, intro, one `.m-entry` per product, sources, note. Getting
  that wrong is what made the products and bioplastic sections look empty.
- **Carousel** (`gallery`) with arrows, counter and video frames, the same on
  phone and desktop. Single-frame galleries hide their arrows and counter.
- **`caption` vs `alt`.** `alt` describes the image for a screen reader and is
  never shown. `caption` is what a reader sees under it, and wins when present.
  The products carousel uses captions of the form *Installation view, Shell
  Cream*, because the descriptions were doing the caption's job badly.
- **Popup captions and credits**, per-image `credit`, `sources` lists, `note`.
- **`goTo`** internal cluster links.
- Map zoom on cluster click raised to a **1.25 minimum**; tall clusters land at
  their top rather than centred.

## 8. Working notes

- **The browser pane is unreliable.** Screenshots come back stale, wrongly
  scaled, or of a previous state; window resizing often doesn't take. Verify by
  measuring the DOM with `javascript_tool`, not by looking. Console errors
  persist across reloads, so a 404 in the log may be from an earlier load —
  check `read_network_requests` before believing it.
- **Images the user attaches in chat cannot be written to disk.** There is no
  tool for it, and the clipboard was empty when tried. They must save the file
  themselves; then it can be optimised in place.
- **Optimise every image on the way in**, with `tools/optimise_images.py`.
  Convention is max 1400px at quality 55 for card media, 2560px at quality 72
  for full page backgrounds. It refuses to flatten a PNG whose transparency is
  actually used, and leaves the original in place so you can compare before
  deleting. The Sargassum set went 16MB → 1.2MB; `Background/` went 26.8MB →
  2.2MB; a 22MB GIF became a 388KB mp4 via ffmpeg (available).
- **Check the assets after any move** with `tools/check_assets.py`. It resolves
  every `url()`, `src` and `href` across the html, css and js, and also lists
  files nothing references.
- Standard verification after any change:
  ```
  overlaps within each cluster, in EN and PT
  overlaps between clusters
  every la/ asset referenced exists and serves 200
  no "[object Object]" in document.body.innerHTML
  node --check on the extracted script
  ```
