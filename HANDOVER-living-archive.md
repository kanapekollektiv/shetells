## 3. Architecture

Three files, no build step. `living-archive.html` holds the markup, the CSS and
the script inline. `lang.js` holds the interface strings. `content.js` holds
every word on the map. No bundler, no framework, nothing to compile.

| Concept | Where | Notes |
|---|---|---|
| Canvas | `.canvas-inner` | Currently 4200×2300. **Recomputed by the packer, don't hand-edit** |
| Pan/zoom | `#viewport`, `translate(tx,ty) scale(s)` | |
| Categories | `CATS` | 9 clusters, each `{key, label, color}`; `label` is bilingual |
| Cluster centres | `CENTERS` | Drives connection lines only. **Regenerated by the packer** |
| Connection lines | `CONNECTIONS` | Open beziers; `bend` sets curve |
| Card layout | `CARDS_LAYOUT` | `[cats[], x, y, w, h, contentId, layout]`. Geometry only. `layout` takes `stackBelow`, `gap`, `mWidth`, `bare` |
| Card content | `CONTENT`, in `content.js` | Every string, keyed by the id above |
| Resolved cards | `CARDS` | Built at load from the two above, in the old shape |
| Side panels | `SECTIONS` | Only `hypersea` has an entry. Largely superseded — see §7 |

### The content split

Copy used to live inline in the card array, which made single lines 8,000
characters long and put the whole map one stray apostrophe away from a blank
page. It now lives in `content.js`, keyed by the id in the sixth slot of each
card. `CARDS_LAYOUT` holds geometry, `content.js` holds words and media paths,
and a resolver right below the array rebuilds the old
`[cats, x, y, w, h, title, content]` shape, so nothing downstream changed.

For whoever edits the copy:

* Strings are written in backticks, so apostrophes are safe.
* A real line break is a paragraph break. Indentation is stripped at load by
  `dedent()`, so keep the text lined up with its entry.
* `txt` is the card, `full` is the popup. The code already falls back to `txt`,
  so only write `full` when the popup genuinely says more.
* `note: 'ml'` expands to the standard ML sentence, held once in `ML_NOTE`.
* An id with no entry, or an entry no card uses, is reported in the browser
  console at load. Neither is visible on the map otherwise.

The migration was verified by resolving all cards and deep-comparing them
against the pre-migration array: identical. Re-verified after the ids were
renamed to readable slugs. (It was 66 cards at the time of that check; **there
are 73 as of 21 Aug** — count them with
`grep -c "^\s*\[\[" living-archive.html` rather than trusting a number
written down here.)

### Card content types

The 7th element decides what renders. All of these are live and in use:

- `{ img, alt }` + optional `caption`, `link`, `credit`, `full`, `sources`, `note`, `mWidth`
- `{ vid }` + optional `poster` — lazily played by `updateVideos()`, **paused below 0.45 zoom**, which is why `poster` matters
- `{ gallery: [{src, alt, caption}] }` — carousel. Frames ending `.mp4` render as
  video. Optional `full`, `entries`, `sources`, `note`
- `{ link, label }` — external link pill
- `{ goTo: 'clusterkey', label }` — internal pill, flies to another cluster
- `{ txt, full }` — text card; `txt` on the card, `full` in the popup
- `{ audio: { title, note, tracks:[{src, label, lang}] } }` **[added 21 Aug]** —
  a small player, built by `buildAudioDeck()`, rendered under the card's
  introduction in both the popup and the mobile notes. Arrows and a chip per
  track; the line plays through on its own. `lang` is `en` or `pt` and says
  which language that recording is actually in
- `{ credits }` + optional `mtNotice: true`
- `null` with a `title` — plain placeholder card
- `null` with no title — coloured band placeholder

Cross-cluster tagging: `[['hypersea','sargassum'], …]`. The **first** tag is the
owning cluster. Extra tags render as dots under the card.

These shapes are unchanged by the content split; they are simply written in
`content.js` now rather than inline.

### Mechanisms you must understand before editing

**`L(value)`** — the bilingual helper. Any string in `CATS`, `CARDS` or
`SECTIONS` may be a plain string or `{ en, pt }`. `L()` returns the active
language and falls back to English. **Every consumer must call it.** Forgetting
it prints `[object Object]` into the DOM — that has happened twice.

**`onLang(fn)`** — registers a callback that re-applies text on language change.
The map is never rebuilt, so pan, zoom and float phase survive a switch.

**`stackBelow: true, gap: n`** — positions a card from the bottom of the
**previous card in the `CARDS` array**, recomputed on every language change.
Essential because text cards hug their content and Portuguese runs 10–20%
longer. Several collisions were caused by fixed `y` under a text card.

**The packer**, `tools/pack_clusters.py`. Cluster positions, `CENTERS`, canvas
size and the SVG size are all generated by it, so re-run it after every content
change. Card positions *within* a cluster are hand-authored; the packer
translates each cluster as a rigid group.

```bash
python3 tools/pack_clusters.py            # dry run, prints what would move
python3 tools/pack_clusters.py --write    # apply
```

Rows, margins, the 210px horizontal gap, the 320px row gap and the per-cluster
vertical stagger are constants at the top of the file, each one commented. A
row's top line is its *smallest* stagger, so the values are relative to each
other and a row does not shift bodily when one cluster leaves it. `FREE` places
a cluster by hand, as an explicit top left corner, for the ones that belong in
the space between rows; nothing checks those for collisions, so check the
neighbours after moving one. A cluster in `FREE` still needs a centre, since the
connection lines read `CENTERS` by key and throw on a missing one, which takes
the whole script out. Every
row needs at least one cluster at stagger 0, or it exits rather than guess. It
takes an optional file path, which is how to try a layout change on a copy
before touching the real page.

It is idempotent, and that is the check: run it twice, the second run should say
`nothing to do`. Run against the layout as it stood on 2026-08-18 it reproduced
all nine cluster positions and the 4200×2300 canvas exactly, changing only the
whitespace and ordering of the `CENTERS` block, which it now writes in row
order.

### Traps that have already bitten

- **No lazy loading on map card images.** The canvas is transformed, and moving a
  transformed ancestor does not re-run the browser's intersection check, so
  images in far clusters never loaded. Panels and mobile notes scroll normally
  and keep `loading="lazy"`.
- **Authored `h` vs rendered height.** Text cards ignore authored height. The
  packer uses authored values, so author them generously or the bbox is wrong.
- **Click detection** is a per-card `pointerdown`/`pointerup` pair, distance
  < 12px and time < 600ms, deliberately bypassing the pan handler. If clicks
  break after a refactor, this is why.
- **`stackBelow` used to be broken on every load, silently.** It measured the
  card above it while the cards were still being built, got zero, and left
  every stacked card sitting at its own gap value in the corner of the canvas.
  A language switch re-ran it and everything snapped into place, which is why
  it looked fine whenever anyone checked. It now watches its anchors with a
  `ResizeObserver`, so a card moves whenever the one above it changes size, for
  any reason. Do not replace that with a load or fonts.ready handler: those are
  guesses about timing and each of them can fire too early.
- **A text card is an opening, not the whole piece.** `.card-text-preview` is
  cut to seven lines with a `max-height`, and the read more hint is a sibling
  rather than inline, because anything inside the cut gets clipped with the
  text. Clicking opens the popup, as it always has. A text card with a `title`
  shows it as a headline, on the card and at the top of its popup, the way a
  gallery does.
- **On a phone the long blocks fold instead**, through `mobileBlock()`. More
  than two paragraphs and the first paragraph stands while the rest slides down
  behind a read more; two or fewer is left alone, since folding two sentences
  only adds a tap. The fold is a class on a wrapper, not a measured height,
  because a height set from script is one more thing that can be raced.
- **Never slice content.js from a section marker to the end of the file.** The
  sections are not in a fixed order, and writing the Toolkit block that way
  deleted the whole Artwork & Exhibition section, eight entries and forty three
  captions, from an uncommitted file. Git could not help and the browser cache
  had already rolled over; it was rebuilt by hand. Cut from one section marker
  to the *next* section marker, and commit before large content edits.
- **Measure the map at desktop width.** Below 768px the map is `display: none`
  and every `offsetHeight` reads 0, so an overlap check will come back clean
  and a `stackBelow` gap will read as a large negative number. Assert
  `window.innerWidth` before trusting any layout measurement, and check for
  cards with zero height as a canary.
- **`stackBelow` anchors to the previous card in the CARDS array**, not to the
  nearest card above it on the canvas. Put a stacked chain immediately after
  the card it hangs from; anything placed between them becomes the anchor. This
  is what put the toolkit links most of a screen below their text card.
- **Always validate after a large edit.** Two syntax errors (doubled `}`) took
  the whole script out. Extract and check:
  ```bash
  python3 -c "import io,re;s=io.open('living-archive.html',encoding='utf-8').read();io.open('/tmp/page.js','w',encoding='utf-8').write(re.search(r'  <script>\n(.*?)\n  </script>',s,re.S).group(1))" && node --check /tmp/page.js
  ```

## 4. Hard constraints

1. **Never rotate cards.** The float animation drifts x/y only. A live `rotate()`
   was found and removed; do not reintroduce it.
2. **Never edit the user's written copy.** Verbatim, including the typo "Here you

   explicit permission for the Sargassum text, where spelling was corrected.
3. **No dashes in prose.** No em dashes, no hyphenated compounds where avoidable.
   Applies to both languages. **[exception, 21 Aug]** The about copy in
   `archive.about.body` and `archive.about.more` keeps its spaced hyphens,
   because Helin asked explicitly for the punctuation to stand as written. Rule
   2 wins over rule 3 where the two collide: it is their copy.
4. **Portuguese is European (pt-PT), addressing the reader as *tu*.** The whole
   of `lang.js` was converted. `document.documentElement.lang` is `pt-PT`.
5. **Text I write carries the ML note**, via `note:`. Copy supplied by the user
   does not. The participant's handwritten water memory does not.
6. Lightbox is `object-fit: contain` — fit, never crop.

## 6. Features built this session

- **Bilingual throughout** via `lang.js` (93 EN / 94 PT keys, parity verified).
  `archive.*` keys: `back`, `contribute`, `hint`, `placeholder`, `read`,
  `readmore`, `sources`.
- **Mobile layout** under 768px: the map is replaced by a plain list of clusters,
  tapping one opens that cluster's content as a scrolling "field notes" column.
  Built from the same `CATS`/`CARDS` data, so clusters gain a mobile view as soon
  as they have cards. A card's `title` leads its section, since on a phone there
  is no card to carry it, and a gallery renders everything the desktop popup
  shows: carousel, intro, one `.m-entry` per product, sources, note. Getting
  that wrong is what made the products and bioplastic sections look empty.
- **Carousel** (`gallery`) with arrows, counter and video frames, the same on
  phone and desktop. Single-frame galleries hide their arrows and counter.
- **Every speculative story names the ecological problem it answers**, as a
  `sources` entry under it: the label states the problem in plain words and the
  link goes to the paper. Verify a DOI through the CrossRef API
  (`api.crossref.org/works/<doi>`) rather than by opening it. Two of the
  citations picked by title lookup on this page turned out to be a COVID
  finance paper and a poplar commission report, and only CrossRef caught it.
- **`mapTitle: true`** prints a card's title under it on the map, so a carousel
  says what it is without being opened. It is opt in because the line adds
  height the packer cannot see: the packer measures the authored `h`, so author
  that box about 40px taller than the card or whatever sits below will end up
  a couple of pixels away.
- **The popup names every cluster a card belongs to**, one chip per tag, the
  owning cluster first. Pass the whole `cats` array to `openGalleryPopup`.
- **`entries` follow their frame when there is one each.** A gallery whose
  `entries` count equals its `gallery` count shows the entry for the current
  image, under that image, changing as you move through it. Any other ratio
  means the notes are about the whole set, and they stack underneath as before.
  The products carousel, 10 frames against 5 entries, still stacks. A per frame
  gallery also moves its `full` introduction above the carousel, so it is said
  once at the top rather than trailing under whichever story you stopped on.
- **`caption` vs `alt`.** `alt` describes the image for a screen reader and is
  never shown. `caption` is what a reader sees under it, and wins when present.
  **A caption says where you were, not what the photograph contains.** *Workshop
  at the Sargassum Museum*, *Walking on the beach*, *Recording on the dunes*,
  *Installation view, Shell Cream*. Never *A shell held up to the mouth*.
  Repeating the same caption across several frames of one session is right, not
  lazy. Every image and gallery frame in the archive now carries one; falling
  back to `alt` is what produced the explaining tone in the first place.
- **Popup captions and credits**, per-image `credit`, `sources` lists, `note`.
- **`goTo`** internal cluster links.
- Map zoom on cluster click raised to a **1.25 minimum**; tall clusters land at
  their top rather than centred.

## 8. Working notes

- **The browser pane is unreliable.** Screenshots come back stale, wrongly
  scaled, or of a previous state; window resizing often doesn't take. Verify by
  measuring the DOM with `javascript_tool`, not by looking. Console errors
  persist across reloads, so a 404 in the log may be from an earlier load —
  check `read_network_requests` before believing it.
- **Images the user attaches in chat cannot be written to disk.** There is no
  tool for it, and the clipboard was empty when tried. They must save the file
  themselves; then it can be optimised in place.
- **Optimise every image on the way in**, with `tools/optimise_images.py`.
  Convention is max 1400px at quality 55 for card media, 2560px at quality 72
  for full page backgrounds. It refuses to flatten a PNG whose transparency is
  actually used, and leaves the original in place so you can compare before
  deleting. The Sargassum set went 16MB → 1.2MB; `Background/` went 26.8MB →
  2.2MB; a 22MB GIF became a 388KB mp4 via ffmpeg (available).
- **Bump `content.js?v=` whenever content.js changes.** Forgetting it once cost
  a session: the browser kept an old copy, the new card found no entry, and it
  rendered as the coloured band placeholder, which looks like a layout bug
  rather than a caching one. The console said so, under a warning nobody read.
- **The same rule applies to `lang.js`, and it was not being followed.
  [corrected 21 Aug]** On 21 Aug the numbers had drifted apart across the site:
  `living-archive.html` asked for `lang.js?v=9`, `hypersea`, `memories` and
  `recorder` for `?v=7`, `thankyou` for `?v=2`, and **`index.html` and
  `stream.html` carried no version at all**. Editing `lang.js` without touching
  those numbers means every page keeps requesting the URL it already has cached,
  and Pages serves these files with `cache-control: max-age=600`, so the change
  simply does not appear. This cost time that day: a correct, verified deploy
  looked broken in the browser, twice. All of them were unified to `?v=10`, and
  `content.js` to `?v=25`.
- **A query string on the *page* does nothing for its scripts.**
  `living-archive.html?v=2` gets you a fresh page which then loads whatever
  `lang.js?v=<old>` it asks for, straight from cache. Bump the script's own
  number, hard refresh (**&#8984;&#8679;R**), or check the bytes with `curl`
  rather than trusting the browser.
- **`drawings/Asset 16.svg` is stroked in white** and is invisible on anything
  pale. It belongs on the landing page's coloured backgrounds. Leave it out of
  anything that sits on a white card.
- **`bare: true`** drops a card's shadow, hairline and corner radius, so the
  artwork sits on the canvas rather than in a box. Used by the drawing loop,
  which should read as an illustration on the map and not as a card.
- **The drawings wobble inside the SVG, not on the card.** The no-rotation rule
  in §4 still holds: the card never turns. Each drawing rocks about its own
  centre, offset from its neighbours so the set never moves as one block.
- **Animated line art is an SVG, not a GIF**, built by
  `tools/build_drawing_loop.py`. It namespaces each drawing's classes and ids,
  which all collide otherwise because they are Illustrator exports that every
  one of them calls `.cls-1` and `clippath`, fits them into a shared frame and
  cross fades between them in CSS. The map zooms, so a GIF would go soft the
  moment anyone zoomed in, and this stays sharp for 40KB. CSS animation inside
  an SVG does run when the file is an `<img>` src, so it needs no card changes.
  Build the frame at the card's own aspect ratio: map cards use
  `object-fit: cover`, and a mismatched frame gets cropped. Leave room for the
  wobble: rotating by `d` degrees grows the drawing's box by roughly
  `h · sin d` on each side, and the card clips with `overflow: hidden`.
  Measure it rather than eyeballing it, by painting the live `<img>` onto a
  canvas and reading the ink bounds. Painting a *fresh* `Image()` gives a false
  reading: it captures the animation at time zero, where everything is
  deliberately transparent.
- **Connection lines use `vector-effect: non-scaling-stroke`.** The canvas is
  scaled by the viewport transform, so a plain stroke thins to nothing when
  zoomed out, which is where the lines were disappearing. The stroke now holds
  its width in device pixels at any zoom.
- **Check the assets after any move** with `tools/check_assets.py`. It resolves
  every `url()`, `src` and `href` across the html, css and js, and also lists
  files nothing references.
- Standard verification after any change:
  ```
  overlaps within each cluster, in EN and PT
  overlaps between clusters
  every la/ asset referenced exists and serves 200
  no "[object Object]" in document.body.innerHTML
  node --check on the extracted script
  ```

## 9. Repository layout

Fonts live in `Fonts/`, images in `img/`, page backgrounds in `Background/`,
living archive media in `la/`, the film's sprite pages in `sprites/`, and the
product hotline recordings in `audio/hotline/` **[added 21 Aug]**. Nothing image
or font shaped sits at the root any more, and every stylesheet link carries a
`?v=` so a deploy cannot leave a visitor on a stale copy. Bump that number when
you change the file.

**[corrected 21 Aug]** That was true of the stylesheets but *not* of `lang.js`
and `content.js`, whose numbers had drifted or gone missing entirely. See §8.
When you change either file, bump it in **every** page that loads it:

```bash
grep -n 'src="\(lang\|content\)\.js' *.html
```
